Slide 3

Pipeline CI/CD

Job qualite

  • checkout du depot
  • installation de Python 3.12 et `uv`
  • demarrage d'un service PostgreSQL
  • restauration du modele chiffre
  • migrations, tests et lint

Job deploiement

  • declenchement sur tag `v*`
  • preparation d'un export propre du depot
  • upload vers Hugging Face Spaces
  • secrets requis : `HF_TOKEN`, `MODEL_ARTIFACT_PASSPHRASE`

Preuve a commenter

Le fichier .github/workflows/ci.yml automatise la qualite et montre une separation claire entre validation technique et deploiement.

Slide 4

API FastAPI et architecture applicative

1. Client -> POST /predict ou GET /health
2. Validation Pydantic du payload et des bornes
3. Chargement du modele XGBoost et preprocessing
4. Calcul de probabilite_attrition, prediction_attrition, threshold
5. Journalisation dans PostgreSQL si la base est configuree
6. Retour JSON et supervision via /health

Endpoints livres

  • GET /health
  • POST /predict
  • GET /docs

Choix d'architecture

  • separation API / modele / DB
  • validation avant inference
  • persistance obligatoire si DB configuree

Slide 8

PostgreSQL, modele de donnees et exemples

Table `prediction_logs`

  • id et created_at
  • request_payload en JSONB
  • score, decision binaire, seuil
  • model_identifier

Artefacts BDD livres

  • scripts/create_db.py
  • scripts/seed_prediction_logs.py
  • sql/create_prediction_logs.sql
  • references/prediction_logs_examples.csv

Exemple de preuve SQL

SELECT prediction_attrition, model_identifier,
       request_payload->>'poste' AS poste
FROM prediction_logs
ORDER BY created_at DESC
LIMIT 1;

Choix technique important

Le `JSONB` permet de conserver le payload complet pour l'audit sans rigidifier inutilement le schema de logging.

Limites, point de vigilance et conclusion

Limites assumees

  • pas de dashboard BI dans ce depot
  • pas de gestion IAM complete

Hugging Face Spaces

  • pipeline de deploiement prepare dans GitHub Actions
  • correctif runtime ajoute dans le depot
  • revalidation publique a rejouer apres redeploiement

Conclusion

J'ai transforme un modele ML en service exploitable avec une API documentee, des tests automatises, une base PostgreSQL de tracabilite et une CI/CD demonstrable face a un responsable technique.
