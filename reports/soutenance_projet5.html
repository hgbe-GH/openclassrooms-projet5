Slide 2

Besoin metier et reponse technique

Besoin

Futurisys souhaite rendre son modele d'attrition utilisable en production, avec une API fiable, des tests, une authentification simple et une base de donnees exploitable pour l'audit.

Reponse

Une application FastAPI qui valide le payload, appelle l'artefact modele, journalise la prediction dans PostgreSQL et expose sa documentation via Swagger.

Slide 3

Architecture de la solution

1. Client -> POST /predict ou GET /health
2. Validation Pydantic du payload et des bornes
3. Preprocessing et chargement de l'artefact XGBoost
4. Calcul de probabilite_attrition, prediction_attrition, threshold
5. Journalisation dans PostgreSQL si la base est configuree
6. Supervision, tests, CI/CD et deploiement Space Docker
Slide 4

API, Swagger et securite

Endpoints

  • GET /health : etat du modele, de la DB et de l'auth.
  • POST /predict : prediction et persistence.
  • GET /docs : Swagger / OpenAPI.

Securisation

  • Header attendu : X-API-Key.
  • Route protegee : POST /predict.
  • Reponse attendue si cle invalide : 401.
  • Erreurs documentees : 401, 422, 503.

Preuve a montrer

Ouvrir /docs pendant la demo pour afficher les schemas Pydantic, les exemples de payload et les erreurs documentees.

Slide 9

Demo courte et conclusion

Scenario de demo en 3 minutes

  1. Lancer l'API localement.
  2. Montrer Swagger sur /docs.
  3. Appeler /predict avec le payload versionne.
  4. Verifier la ligne ajoutee dans PostgreSQL.
  5. Montrer les tests et le workflow CI/CD.

Limites et suites

  • authentification simple par cle API, pas d'IAM complet
  • pas de dashboard BI dans ce depot
  • revalidation publique du Space apres redeploiement
